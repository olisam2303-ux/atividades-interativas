ATIVIDADE PROPOSTA

O que vocês vão resolver

A NuvemFit é um aplicativo de treinos que roda inteiramente na nuvem. Sua API principal, /treinos, é monitorada por um painel gerenciado que exibe duas métricas centrais: a latência e a taxa de erro. A dupla analisa as duas tabelas de métricas, localiza o intervalo com comportamento anormal e investiga se as duas métricas apontam para uma causa comum.

OBJETIVOS

O que vocês vão aprender aqui

  • ✓compreender o que são p50, p95 e p99 como percentis de latência;
  • ✓diferenciar latência de taxa de erro como métricas complementares;
  • ✓interpretar tabelas de métricas para localizar comportamento anormal;
  • ✓relacionar a coincidência entre métricas diferentes a uma possível causa comum.
ENTENDA

Percentis de latência e taxa de erro

Painéis de nuvem geralmente mostram o tempo de resposta em percentis — cada um revela uma parte diferente da experiência dos usuários.

O p50 sozinho pode esconder um problema que só aparece nos percentis mais altos.

São métricas diferentes — uma mede tempo, a outra mede falhas — mas juntas contam mais da história do que cada uma isolada.

FLUXOGRAMA

Como ler duas tabelas de métricas juntas

O fluxo abaixo é o método repetido para cada horário registrado — ele não diz em qual horário o comportamento muda, nem se as métricas se relacionam, só o caminho da leitura.

O Relatório pede para aplicar esse método às tabelas reais da API /treinos.

Como ler o fluxograma

  1. 1Compare sempre com os horários vizinhos — um valor sozinho não diz se está dentro ou fora do padrão.
  2. 2O p99 pode se comportar de forma bem diferente do p50 no mesmo horário — não ignorem os percentis mais altos.
  3. 3Observar as duas tabelas juntas, não cada uma isolada, é o que pode revelar se existe uma relação entre elas.
  4. 4O fluxograma não diz em quais horários o comportamento muda, nem se as métricas se relacionam — essa leitura é a tarefa de vocês no Relatório.
